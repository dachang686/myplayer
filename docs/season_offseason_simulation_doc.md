# BuildPlayer 赛季模拟与休赛期推演 (Offseason) 逻辑文档

本文档详细解析了 `js/core_game_logic.js` 中关于赛季结束、休赛期演进（球员老化、涨跌、合同、自由市场与交易）的所有算法计算过程。

> [!NOTE]
> 本文档所有论断均已与源代码逐行交叉比对核实（最后校验时间 2026-08-08）。

---

## 1. 赛季结算与颁奖 (`endSeason` & `calcSeasonAwards`)

当常规赛最后一场比赛打完后，引擎触发赛季结算：
1. **场均数据归档**：将 `STATE.season.playerStats`（累计数据）除以出场数，转换成 `avgStats`（保留1位小数）。
2. **生成奖项 (`calcSeasonAwards`)**：通过 `calcAllStarScore` 公式给全联盟球员打分，评选出常规赛 MVP、DPOY（最佳防守球员）、一阵、防阵等，并存入 `STATE.season.awards`。

---

## 2. 球员老化与属性涨跌 (`evolveLeague`)

休赛期开启的第一步，是对全联盟（`NBA2K_DATA`）每一个球员进行年龄与能力的重算。

### 2.1 年龄计算
系统会通过 `getLeaguePlayerAge` 动态获取/推算球员的当前年龄，并在该赛季推演时 `+1` 岁。
* **勒布朗特殊保护**：`LEBRON_JAMES_SPECIAL_RULE` 定义了特殊的初始年龄和受保护退役年龄，在保护年龄之前退役概率强制为 0。

### 2.2 能力值 (OVR) 涨跌公式
球员的 OVR 变化量 (`change`) 由三个加权因子组成：
```javascript
var change = ageFactor * 0.5 + volFactor * 0.3 + randFactor * 0.2;
```
1. **年龄因子 (`ageFactor`)**:
   * **≤ 22岁**：大幅成长，`1 + rngNext() * 1.5`（期望值约 +1.75）
   * **23 - 28岁**：巅峰期小幅震荡，`(rngNext() - 0.5) * 1.5`（期望值约 0）
   * **29 - 33岁**：衰退期，`-1 - rngNext() * 1.5`（期望值约 -1.75）
   * **≥ 34岁**：断崖式下滑，`-2 - rngNext() * 2`（期望值约 -3.0）
2. **潜力波动因子 (`volFactor`)**: `(rngNext() - 0.5) * volatility * 0.6`。`volatility` 是球员自带的随机基因（1-4），数值越大越不稳定。
3. **纯随机因子 (`randFactor`)**: `(rngNext() - 0.5) * 1.5`。
4. **巨星光环加成（叠加，不在公式权重内）**: 如果 `isMvpStar(p)` 为真且年龄 `≤ 26`，额外追加 `+0.6 + rngNext() * 0.8`（期望值约 +1.0）。

最终 `change` 会被 `Math.round(change * 2) / 2` 四舍五入到 0.5 步长，新 OVR 限制在 `[55, 99]` 区间。

### 2.3 面板属性同步
算出了新 OVR 后，计算 `ratio = Math.round(newOvr) / p.ovr`，将这个比例乘到该球员所有的具体属性上（三分、内防、运动能力等），各项属性限制在 `[25, 99]` 区间内。

---

## 3. 退役系统 (Retirement)

每年能力涨跌后，系统会进行退役概率判定：

| 条件 | 退役概率 |
|------|----------|
| 勒布朗且 < 保护年龄 | 0% (豁免) |
| ≥ 40岁 | 100% (强制退役) |
| ≥ 38岁 | 50% |
| ≥ 36岁 | 25% |
| ≥ 34岁 且 OVR < 75 | 35% |
| 其他 | 0% |

被判定退役的球员从花名册中永久删除，记录在 `STATE._leagueChanges.retired` 中。

---

## 4. 补充新秀 (Rookies Fill)

退役后如果某支球队人数不足 **18 人**，引擎会调用 `generateRookie()` 从 `ROOKIE_NAMES` 库中随机抽取姓名并随机生成初始能力，强行将各队大名单补齐到 18 人。

> [!IMPORTANT]
> 这个补齐发生在 `evolveLeague` 内部，在退役判定之后、合同处理之前。也就是说，退役空出的位置会立刻被新秀填满，然后这些新秀还会参与后续的合同初始化。

---

## 5. 合同与留队系统 (Contracts & Retention)

### 5.1 合同初始化
首次进入休赛期时（`STATE._contractsInited === false`），引擎会为所有未设定合同的球员按年龄分配初始合同：

| 年龄段 | 合同年限 |
|--------|----------|
| ≤ 23岁 | 2 + random(0-2) 年 |
| 24-26岁 | 2 + random(0-1) 年 |
| 27-30岁 | 1 + random(0-2) 年 |
| 31-33岁 | 1 + random(0-1) 年 |
| ≥ 34岁 | 1 年 |

### 5.2 年度合同扣减
每年 `p.contract--`。合同到期（`≤ 0`）后触发留队判定。

### 5.3 留队概率 (`stayRate`) 公式
```javascript
var stayRate = Math.max(0.1, Math.min(0.95, 0.80 * teamFactor * starFactor * trendFactor));
```
* **战绩因子 (`teamFactor`)**：根据该球队历史胜率（`STATE._teamHistory`）。

| 球队历史胜率 | teamFactor |
|-------------|------------|
| ≥ 65% | 1.1 |
| ≥ 55% | 1.0 |
| ≥ 45% | 0.9 |
| ≥ 35% | 0.75 |
| < 35% | 0.6 |

* **球星因子 (`starFactor`)**：OVR ≥ 88 的巨星乘 0.9（更倾向去自由市场试水），其他球员乘 1.0。
* **趋势因子 (`trendFactor`)**：如果球队连续两年胜率环比下降 > 2%，乘 0.85；连续两年环比上升 > 2%，乘 1.1；其他情况 1.0。

留队 → 通过 `randomContractByAge` 分配新合同年限。
离队 → 进入 `STATE._freeAgentPool`。

---

## 6. 自由市场签约分配 (`assignFreeAgents`)

### 6.1 分配顺序
* **自由球员**：按 OVR 从高到低排序。
* **球队**：按上赛季胜率从低到高排序（弱队优先挑选）。

### 6.2 签约限制
* **禁止回原队**：`fa._origTeam === t` 时跳过。
* **大名单上限**：每队最多 18 人。
* **位置需求优先**：球员只会加入**该位置人数不足 2 人**的球队。
* **防巨星抱团（OVR > 86 的球星专属限制）**：
  1. 如果目标球队本轮自由市场**已签过一名 OVR > 86 球星**（`starSignedTeams[t]`），则拒绝加入。
  2. 如果目标球队阵中已有一名**同位置（`canPlayPosition` 检查通过）且 OVR ≥ 84** 的非玩家球员，则拒绝加入。

> [!IMPORTANT]
> 防抱团机制检查的是**同位置**的球星，而不是全队所有位置。如果一支球队的 PG 有 85 OVR 球星，一个 87 OVR 的 C 自由球员仍然可以加入该队。

### 6.3 Fallback 机制
如果首轮遍历找不到满足位置需求的球队，球员会进入 fallback 循环，在**不考虑位置需求**的情况下加入任何有空位（< 18 人）的球队（但仍遵守防抱团和禁止回原队规则）。

---

## 7. 自动交易系统 (`processTrades`)

在自由市场结束后，联盟内部会发生小规模的自动交易。

### 7.1 交易逻辑
引擎的交易并非同位置互换，而是**互补需求交换**：
1. 为每支球队计算"最薄弱首发位置"（`needs[t]` = 首发 OVR 最低的位置）。
2. 在打乱顺序的球队列表中寻找**需求互补**的两支球队（A 需要 PG，B 需要 C）。
3. A 从自己的板凳中找一个能打 C 位的球员给 B，B 找一个能打 PG 位的球员给 A。

### 7.2 交易限制
* **OVR 差值上限**：交换双方 OVR 差距不超过 **8**（代码 `diff <= 8`）。
* **交易总量上限**：每个休赛期最多 **10 笔**交易。
* **每队一次**：已发生过交易的球队不会再参与后续交易（`tradedTeams` Set 控制）。
* **不可交易名单**：
  * OVR > 92 的建队基石
  * 玩家角色 (`_isUser`)
  * 刚签下新合同的球员 (`_justSigned`)
  * 名字包含 `Rookie_` 的新秀

### 7.3 交易后更新
交易完成后，引擎会立即重算双方球队的 `needs`（最弱位置），以便后续的交易配对能考虑到最新阵容变化。

---

## 8. 初始化新赛季 (`resetForNewSeason`)
完成以上所有的花名册变动、属性涨跌后：
1. 调用 `saveCurrentSeasonToCareer()` 将本赛季数据归档到 `STATE.career.seasons`。
2. 清空 `_rngState`，让新赛季第一次随机调用时重新取种子，避免沿用上一赛季的随机序列。
3. 清空 `STATE.season`（胜负归零、累计数据清零、事件状态重置）。
4. 重新初始化联盟排名 `initStandings()`。
5. 重新编排真实赛程表 `buildRealSchedule()`。
6. 渲染全新的赛季主界面。
