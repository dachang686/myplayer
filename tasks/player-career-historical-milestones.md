# 球员生涯历史里程碑与纪录殿堂

- 状态：待开发
- 优先级：P1
- 范围：个人球员生涯模式的历史累计统计、里程碑事件与展示
- 目标：让玩家的比赛结果沉淀为可追溯的联盟历史，形成“冲纪录”和“成为传奇”的长期可玩目标。

## 玩法目标

当前生涯数据主要服务于赛季和单个球员展示，缺少“我正在逼近联盟历史纪录”的长线反馈。新增系统后，玩家可持续追逐以下目标：

- 生涯总得分、总篮板、总助攻、总抢断、总盖帽的联盟历史前五。
- 超越历史第 5、第 3、第 1 时的即时生涯事件。
- “411 工程”：生涯累计 `40000 分 + 10000 篮板 + 10000 助攻`。
- 后续可扩展的传奇目标，例如 30000 分、10000 助攻、10000 篮板、单项历史第一、五项前五等。

## 设计原则

1. 纪录以生涯正式比赛的累计数据为准，常规赛和季后赛是否分别统计必须与项目现有统计口径保持一致，并在页面明确展示。
2. 历史纪录是独立的持久化数据，不应临时从页面 DOM 或比赛日志重新推断。
3. 里程碑事件只触发一次。模拟重放、读档、刷新、补算和同一场比赛重复结算都不得再次弹出或重复授予荣誉。
4. 仅在比赛统计完成写入后检查纪录，确保事件的数值、名次和赛季信息一致。
5. 不修改经理模式的 `MANAGER_STATE` 或经理模式存档。本任务只处理个人球员生涯；未来如需经理模式历史纪录，应通过独立适配任务接入。

## 数据模型

在现有个人生涯存档中增加版本化、可迁移的历史记录结构。字段命名可按现有项目习惯调整，但应达到以下语义：

```js
legacyRecords: {
  version: 1,
  categories: {
    points: [/* 前五，按 value 降序 */],
    rebounds: [],
    assists: [],
    steals: [],
    blocks: []
  },
  milestones: {
    fourOneOne: {
      pointsTarget: 40000,
      reboundsTarget: 10000,
      assistsTarget: 10000,
      achieved: false,
      achievedAt: null
    }
  },
  triggeredEventIds: {}
}
```

每条前五纪录至少保存：

```js
{
  playerId,
  playerName,
  teamId,
  value,
  season,
  date,
  source // 现役、历史预置、退役等，便于未来扩展
}
```

要求：

- `categories` 始终按数值降序，最多保留 5 条。
- 同一球员在同一类别只保留其当前最高的生涯累计值，不能因每场更新形成多条重复名次。
- 玩家球员进入前五后，其数值应随生涯累计继续更新，而非冻结在首次入榜数值。
- 历史基准数据来源必须明确。若项目当前没有真实 NBA 历史纪录数据，第一版可采用项目内置的“联盟历史基准”，但不得伪称为真实精确统计。

## 触发规则与反馈

### 五项历史榜超越

比赛结算后，对玩家球员的生涯累计 `points/rebounds/assists/steals/blocks` 执行：

1. 更新该类别前五。
2. 比较本场结算前后的玩家名次。
3. 仅在首次达到以下节点时触发事件：
   - 首次进入历史前五。
   - 首次进入历史前三。
   - 成为历史第一。
4. 事件 ID 必须稳定，例如：`legacy:points:top5:<playerId>`、`legacy:assists:first:<playerId>`。

### 411 工程

- 三项进度使用玩家生涯正式比赛累计：得分 40000、篮板 10000、助攻 10000。
- 生涯页和历史殿堂显示三条独立进度及总达成状态。
- 每个单项首次完成可给轻量提示；三项同时完成时触发一次最高规格庆典。
- 达成信息保存达成赛季、比赛 ID/日期和球队。

### 事件分级

| 节点 | 反馈 |
| --- | --- |
| 历史前五 | 比赛结算新闻 + Toast/事件卡 |
| 历史前三 | 事件卡 + 生涯荣誉更新 |
| 历史第一 | 全屏纪录事件、撒花/庆祝动画、纪录海报入口 |
| 411 工程 | 全屏传奇庆典、永久勋章、历史殿堂置顶 |

庆祝动画必须可跳过、支持减少动态效果偏好，且不能阻塞存档完成。

## 页面与可见性

新增或扩展一个“历史殿堂 / 传奇纪录”入口，至少包含：

1. 五项历史前五榜，可切换分类。
2. 玩家所在名次与距上一名差值；未进榜时显示距第五名差值。
3. 411 工程的三项进度、已完成状态和达成赛季。
4. 最近的纪录事件时间线，包括被超越的原名次或原纪录保持者。
5. 玩家获得的纪录/传奇勋章。

文案需区分“联盟历史基准”和“本存档历史”。不要把虚构联盟或项目内置数据标成真实 NBA 官方历史纪录。

## 存档与兼容性

1. 为现有个人存档增加显式版本迁移。
2. 旧存档缺失 `legacyRecords` 时必须创建默认结构，不能阻塞读取。
3. 已有生涯累计数据应在首次迁移时补算一次，避免老玩家必须再打一场才显示当前纪录进度。
4. 迁移后同一存档反复读取不得重复补发历史事件。
5. 不读取或写入经理模式 `court_forge_manager_v1` / `manager_saves` / `manager_slot_1`。

## 验收与测试

新增或扩展验证脚本，覆盖：

1. 五项类别各自正确排序、只保留五条、无重复球员条目。
2. 玩家从榜外进入第 5、从第 5 进入第 3、成为第 1 时分别只触发一次。
3. 同一场比赛重复结算、读档、刷新、补算不会重复创建事件或勋章。
4. 411 工程在三项各自完成前不触发总成就，三项全达成后仅触发一次。
5. 旧个人存档迁移后可展示正确累计进度，且不污染经理模式存档。
6. 生涯结束、退役、换队后纪录仍可查询。
7. 真实页面冒烟：完成一场跨纪录比赛，确认结算事件、庆祝、存档、刷新和历史殿堂数值一致。

修改后继续运行所有受影响的个人生涯回归脚本，并记录实际结果。

## 修改边界

- 允许：个人模式的存档迁移、正式比赛结算、事件注册、个人生涯页面和专用验证脚本。
- 禁止：修改经理模式文件、删除既有玩家存档、重置用户历史数据、将同一奖励重复写入成就系统。
- 不包含：真实 NBA 全历史数据爬取、薪资/交易、经理模式接入。

## 完成标准

- 玩家可明确看到自己五项累计数据相对于历史前五的位置。
- 纪录超越与 411 工程具有一次性、可回看、可持久化的反馈。
- 老存档可安全进入，现有个人模式回归无退化。
- 与经理模式保持代码和存档隔离。
